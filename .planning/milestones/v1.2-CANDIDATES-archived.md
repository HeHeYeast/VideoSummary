## 锁死的设计决策（不再讨论）

### D-01：知识库消费者 = Claude，不是用户 ad-hoc grep

**Why：** 用户原话——"开 claude code 会话，说明需求，让他给我推荐一些我需要学习查看的视频总结文档"

**How to apply：** 索引格式优先 Claude 友好（结构化 JSON），不优先人类 grep 友好。Markdown 形式索引一律不做（_glossary.md 已是术语索引，再加 _index.md 职责重叠）。

### D-02：颗粒度 = summary 级 keywords/topics + chapter 级导航锚点

**Why：** 用户原话——"逐个遍历 chapter 来获取关键词不太合理"。每 chapter 重新抽 keywords 是过度切碎；keywords 在 summary 维度匹配，chapter 只做"找到之后跳转"用。

**How to apply：** index.json schema = summary 一层 keywords/topics + chapters 数组（chapter 内只有 title + timestamp + 1-2 行 excerpt，**无独立 keywords 字段**）。

### D-03：keywords/topics 来源 = Claude 自动抽 + glossary 复用

**Why：** 守 v1.1 D-03 自动化优先（"任何用户必须做的方案先 reject"）；用 v1.1 已 ship 的 `output/_glossary.md` 做术语标准化兜底，避免"LoRA / Lora / low-rank adaptation"分裂。

**How to apply：** Phase 7.6 抽 keywords 时优先复用 `_glossary.md` 已有 H2 anchors 作为 keyword 候选；新概念才创造新 keyword。

### D-04：topic taxonomy = 预定义 + Claude 申请新增

**Why：** 用户原话——"给出一组预定义的 topic，然后 claude 从中挑，如果 claude 需要新增主题关键词可以提出请求，一个视频也可以提出多个新增关键词请求"。本质是 v1.1 K5 边界的延伸：Claude 是决策者（选 topic / 提议新 topic），但 taxonomy 是显式 governance 文件。

**How to apply：**
- 文件: `output/_topics.md`（顶层 governance，跟 `_glossary.md` 同级）
- 顶部 = 已批准 taxonomy（按 category 树状）
- 底部 = `# Pending` 段（Claude 申请的新 topic 在这）
- Claude 写 index.json 时只能从已批准段选；都不合适 → append 到 `# Pending`，该 chapter 的 `topics` 字段标 `["pending: <name>"]`
- 用户 governance 节奏：偶尔（一周/一月）打开 `_topics.md` review pending 段，批/拒/改

### D-05：初始 taxonomy = Claude bootstrap from 23 archives

**Why：** 已有 23 条真实数据（17 v1.0 archives + 6 队列）作 ground truth；让 Claude 一次性扫归纳比凭空想准 + 比"完全空 taxonomy 渐进起步"快。

**How to apply：** v1.2 ship 一个 `python -m agent.tools topics bootstrap` 跑一次，扫 17 archives 的 summary.md → 提议一组初始 taxonomy → 写到 `_topics.md` 顶部的批准段（首次 bootstrap 可以默认就批，因为是从真实数据归纳）。同时给 6 队列视频留位（它们走 v1.2 新流程时再申请）。

### D-06：backfill = v1.2 ship 时一次性 17 v1.0 archives + 6 队列走新流程

**Why：** 知识库核心价值在"已有内容能查"——空载没意义；index.json 是新 sidecar 不破 D-29 byte-equal（replay test 只比 summary.md / segs.json / paragraphs.json / meta.json 4 个核心文件）。

**How to apply：**
- v1.2 phase 设计专门留一个 plan 跑 17 archives backfill：用 `topics bootstrap` 出来的 taxonomy → `python -m agent.tools index backfill --all`
- 6 队列视频不需要 backfill：处理时通过新流程（Phase 7.6）同步生成
- D-29 invariant 不破：replay test 看到 17 archives 多了 `index.json` sidecar 不会 FAIL

### D-07：backlink drop（不做跨 summary 引用）

**Why：** 用户原话——"先 drop 吧，我感觉作用也不大"。single-user 23 条规模 over-engineering；backlink 实际场景（你看 BV999 时翻末尾找 BV123）不会真发生；Claude 推荐用 `output/.index.json` 直接做即可，不需要 backlink。

**How to apply：**
- index.json schema **不含** `related_slugs` 字段
- summary.md **不加** "## 相关推荐" 段
- 跨 summary 关联完全靠 Claude 在会话里 `Read .index.json` 即时计算

### D-08：顶层聚合 `output/.index.json` 自动同步 + 手动 rebuild CLI

**Why：** 守 D-03 自动化优先（默认自动）；同时给手动 rebuild 兜底应对 backfill / debug edge case。

**How to apply：**
- 自动：`/summarize-video` Phase 7.6 写完 per-slug `index.json` → 立刻扫所有 `output/*/index.json` rebuild 顶层
- 手动：`python -m agent.tools index rebuild` CLI（backfill phase 一键收尾用）
- 文件 = 所有 per-slug 的扁平合并（无 backlink），让 Claude 1 次 Read 拿全 23+ 条概览

### D-09：Claude 推荐 entry point = 自然语言（不加 slash command）

**Why：** 用户原话——"开 claude code 会话，说明我当前的需求"，已习惯自然语言；slash command 是 nice-to-have 不是必须；少加一个 phase。

**How to apply：** CLAUDE.md 加一段 prompt rule（mirror v1.1 FORBIDDEN list 那种字面规则）：
> "用户提到 '相关视频' / '我之前看过' / '推荐' / '学过吗' / '找一下我' / 类似查询意图时，FIRST ACTION：`Read output/.index.json`，再做 keyword / topic 匹配回复（输出 top-N 推荐 + 各自 chapter 进入点）。"

## 候选 Requirements（按优先级）

### 🔴 必做

#### KB-01: Per-slug `index.json` 生成（中颗粒）

**must-haves:**
- Schema 锁: `slug / title / duration_s / mode / topics[] / keywords[] / tldr_oneliner / chapters[]` (chapter = `title + start + excerpt`)
- 写在 `/summarize-video` Phase 7.6（Phase 7 写完 summary.md 之后、Phase 8 cleanup 之前）
- Keywords 抽取时优先复用 `_glossary.md` 已有术语
- topics 必须从 `_topics.md` 已批准段选；不合适 → 申请到 Pending
- 老归档 backfill 走同一个 generator（保证一致性）
- D-29 不破: index.json 是新 sidecar，replay test 不需要修改

#### KB-02: Topic taxonomy governance

**must-haves:**
- `output/_topics.md` 文件结构：顶部分类树（已批准） + 底部 `# Pending` 段
- `python -m agent.tools topics bootstrap` — 扫 17 archives 提议初始 taxonomy（首次 bootstrap 可默认批）
- `python -m agent.tools topics audit` — 列所有 pending + 各 topic 引用计数 + 孤儿 topic 检测
- `python -m agent.tools topics resolve <pending-name> [--rename <new>]` — 把 pending 挪到正式 topic（自动更新所有引用 index.json）
- Claude 申请新 topic 的 prompt rule 锁定（必填字段：申请来源 slug + chapter title + 提议理由）

#### KB-03: 顶层聚合 `output/.index.json`

**must-haves:**
- Phase 7.6 写完 per-slug `index.json` → 立刻扫所有 `output/*/index.json` rebuild 顶层（atomic write）
- `python -m agent.tools index rebuild` 手动兜底 CLI
- Schema = 扁平 dict (`{"<slug>": <per-slug-index>, ...}`)，无 backlink 字段
- 体积控制：每条 ~ 100-300 字 × 23 条 ≈ 5-10KB，Claude 1 次 Read 无压力
- Stale detection：如果某 per-slug index.json 比顶层 .index.json 新 → rebuild 时自动检测并提示

#### KB-04: 23 archives + 6 队列 backfill（一次性）

**must-haves:**
- v1.2 phase 专门 plan：(1) `topics bootstrap` → (2) 用户 review _topics.md pending → (3) `index backfill --all` 给 17 archives 写 index.json → (4) `index rebuild`
- 6 队列视频不需要 backfill（处理时新流程同步生成）
- backfill 是 idempotent：已有 index.json 的 slug 默认 skip（除非 `--force`）
- 失败模式：某 slug summary.md 损坏 → 单 slug 失败但其他继续，最后报告失败列表

#### KB-05: CLAUDE.md prompt rule（Claude 推荐意图触发）

**must-haves:**
- 触发 phrase 锁定：'推荐' / '相关' / '我之前看过' / '学过' / '找一下我' / '哪些视频' / '类似查询意图'
- FIRST ACTION: `Read output/.index.json`（读不到 → 提示用户跑 `index rebuild`）
- 然后 keyword + topic 匹配 → 输出 top-3 推荐 + 每条带"建议进入点"（chapter title + timestamp）
- 推荐回复格式锁：每条推荐 = 1 行 slug + title + 共享匹配信号 + 1 行 tldr + 1-3 个 chapter 入口
- mirror v1.1 anti-hallucination 规则：FORBIDDEN 编造 slug；FORBIDDEN 推荐 .index.json 里没有的视频

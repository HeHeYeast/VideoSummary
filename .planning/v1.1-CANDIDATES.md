## 锁死的设计决策（不再讨论）

### D-01：每篇 summary 自包含、零基础视角（方案 A）

**Why：** 用户原话——"我们不能假定我的阅读顺序，也不能假定我阅读后一定有理解"。

**How to apply：**
- 每篇 summary 第一次出现新术语都加"小白注解"段（≤ 3 句话）
- 维护 `output/_glossary.md` 累积所有术语作为兜底（不依赖它，但有它）
- 每篇开头加"读这篇前你需要知道什么"段（3-5 行先决条件 + 你不需要知道什么）
- **接受 summary 篇幅变长**（30 分钟视频可能涨到 1000+ 行），不做折叠 / 拆分妥协

### D-02：正确性校验三层叠加（A 自检 + B 溯源 + C 二次复审）

**Why：** 用户原话——"尽可能避免文档撰写中的人工参与，做到高度自动化甚至完全自动化"。

**How to apply：**
- **A 层（自检）：** 写完 summary 后，Claude 自己再读一遍，对每个具体 claim 标 confidence；< 80% 的句子加 `[?]` 标记
- **B 层（行内溯源）：** 每个 claim 后加 `[seg_NNNN_NNNNNN.jpg @ HH:MM:SS]` 行内引用 token
- **C 层（二次复审）：** spawn 独立 reviewer agent，拿 paragraphs.json + 关键帧重新校对，输出 `<slug>-REVIEW.md` 列 confidence < 70% 的句子 + 修复建议

### D-03：自动化优先原则

**Why：** 同上，避免人工参与。任何"需要用户手动做"的环节都是 v1.1 的优化目标——包括用户提供 glossary、用户对齐时间戳、用户挑下一条视频等。

**How to apply：** 所有候选 requirements 必须满足"100% 自动 / Claude 自决 / 用户零参与"。任何"用户提供 X"的方案先 reject。

## 候选 Requirements（按优先级）

### 🔴 必做

#### CORR-01：ASR 转录术语自动校正（3 层）

**问题：** v1.0 工具链所有错误的源头。`Flux→Flox` / `Mucha→木下` / `IFRIT→Aphrit` / `LoRA→Lora/LOL/Laura` 等术语错全靠 plan.md 手写校正表硬扛。

**3 层方案：**
- **L1 检测：** 转录后 Claude 扫 segs.json，自动识别"罕见字组合 / 高频但拼写不一致 / 中英混杂异常"等可疑词，写到 `output/<slug>/transcribe_warnings.json`
- **L2 上下文修复：** Claude 拿 segs.json + meta.json（标题 + UP 主 + 描述），对每个可疑词推断真实拼写。比如标题里有 "LoRA"，转录里 "Lora/LOL/Laura" 全部归一为 LoRA
- **L3 多模态兜底：** 关键截图（标题板 / 工具 UI）里如果出现该词的图像形态，多模态读图比较确认拼写

**实现拆分：**
- L1 是新工具或 Claude 的 prompt-engineered 任务（待研究哪个 ROI 高）
- L2 / L3 是 Claude 写 plan.md 阶段的标准动作

**must-haves：**
- 输出 `transcribe_warnings.json` schema 锁定（per-warning 包含 paragraph_id / suspect_text / suggested_text / confidence / evidence_source）
- L2 修正后 Claude 在 plan.md 顶部记录"已自动修正的术语"清单（透明性）
- D-29 spirit：未触发任何 warning 的旧视频，行为 byte-equal v1.0

#### CORR-02：Summary 自检 + 行内溯源（B 层 D-02）

**must-haves：**
- 写作 prompt 强制：每个截图引用、每个 claim、每个具体参数值后加溯源 token
- 溯源 token 格式锁：`[<frame_filename> @ HH:MM:SS]` 或 `[para_ID @ HH:MM:SS]`
- 写完后 Claude 自检 pass 强制：逐句 confidence 评分，< 80% 加 `[?]`，summary 末尾汇总有几条 `[?]` + 总 claim 数

#### CORR-03：第二 agent 复审（C 层 D-02）

**must-haves：**
- 新 agent 类 `gsd-summary-verifier` 或类似——拿 summary.md + paragraphs.json + 关键帧 + plan.md 跑校对
- 输出 `<slug>-REVIEW.md` 列出 critical / warning / info 三级问题，对照 plan.md mode 分类规则、format-spec 4 项不变量、术语一致性
- 高严重度问题自动触发 summary 重写（最多 1 轮，避免无限循环）
- token 成本预估：summary 写作的 80-100%（与 summary 体量同级）

#### TEACH-A：每篇自包含的零基础形态（D-01 落地）

**must-haves：**
- 写作 prompt 强制：每个新术语第一次出现加 inline 注解 `术语 (English/中文释义)` + 后续可选 `(详见 output/_glossary.md)`
- summary 顶部固定结构：标题 / UP / 时长 / 链接 → "你需要知道什么 / 你不需要知道什么" → "5 分钟速读版"（方案 D，下面） → 正文
- `output/_glossary.md` 跨 summary 累积，不强校验，每篇 summary 自动 append 自己引入的新术语 + 释义

### 🟡 想做

#### TEACH-B：长 summary 顶部速读版

**问题：** 30 分钟视频 + 方案 A → 估计 ~1000 行 markdown。新读者可能看不下去。

**方案：** 文件顶自动加"5 分钟速读版"块（10-15 行：核心结论 / 工作流速查表 / 必看时间戳 3-5 个）。**不**做拆分（接受变长 D-01）。

#### TOOL-A：Mode 分类辅助信号（mode_signals.json）

**问题：** 现在 Claude 凭感觉判 mode（4 选 1）。判错的代价 = 整篇按错形态写 → 全篇重写。在方案 A 下重写代价更大。

**方案：** 新工具 `python -m agent.tools mode_signals <paragraphs.json> --out <slug>/mode_signals.json`。计算几个客观信号：
- 代码 fence 出现率（高 → replicate-guide）
- 时间戳里"步骤 1/2/3 / 第 X 步"出现率（高 → replicate-guide）
- 提问句式占比（高 → interview-distillation 或 concept-explanation）
- 嘉宾切换信号（"今天嘉宾是 X" / "你认为 X" / 多 speaker turn）→ interview-distillation
- 跨工具/跨场景对比信号（"工具 A vs 工具 B" / "在 X 场景下 / 在 Y 场景下"）→ extension-applications

K5 边界：工具只输出 signals + 推荐 mode，**Claude 仍是决策者**。

#### TOOL-B：抽帧策略辅助（schedule_suggestion.json）

**问题：** 现在每条视频要手工写 fps 段策略。Phase 4 已有 `detect_scenes` + `detect_silence` 数据，但没有自动喂给 Claude 写 schedule.json。

**方案：** 新工具 `python -m agent.tools schedule_suggest <slug> --out <slug>/schedule_suggestion.json`。组合 paragraphs.json + scenes.json + silence_map.json：
- 静音区间 → fps 0.05 或 skip
- 场景切换密集区 → fps 0.3-0.4
- 长段无场景切换（讲解段）→ fps 0.1
- 自动加 FPS-04 silence-coverage 兜底

K5 边界：工具输出建议，**Claude 拿建议 + 自己读 paragraphs.json 决定最终 schedule.json**。

- 第 3-5 条视频跑完，痛点没新增
